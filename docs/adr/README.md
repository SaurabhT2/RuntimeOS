# Architecture Decision Records — Index

Twenty-six ADRs are on record, spanning EM-0 through EM-10 (plus the
EM-10 Engineering Rework).
`0000-template.md` is the template used to write all of them, not a
decision itself.

Status legend: **Accepted** decisions are settled and reflected in the
codebase as implemented. **Proposed / draft** ADRs document a real,
verified inconsistency between the frozen Architecture Specification and
the implementation as it exists today; each was raised because a later
milestone's package correctly implemented its own spec section but, in
doing so, exposed a gap or contradiction one layer up. They are recorded
rather than silently resolved, per the project's "document, don't invent a
solution" rule for cross-milestone architectural findings. None of the
open items has been decided by the Architecture Review Board yet.

| [0026](0026-budget-spend-recording-scope.md)               | EM-10 Rework — `BudgetLedger.recordSpend` wiring scoped to `execute()`, not `executeStream()`             | Filed by the EM-10 Engineering Rework Order's Finding 1 fix. `orchestrator`'s new, generic `onExecutionCompleted` hook (gated on success, never on a cache hit or failure) is wired to `BudgetLedger.recordSpend` at `gateway-runtime`'s composition root — the one place already permitted to import every concrete implementation at once, so no new package-boundary edge is introduced. Deliberately scoped to `execute()` only; `executeStream()`'s cancellation semantics have no architecture-defined "successful completion" moment to hook, and is left as a named, disclosed gap rather than guessed at. |
